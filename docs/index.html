Preparação da estação de trabalho

O trabalho começa antes do primeiro código: verifique seu repositório, crie uma branch pessoal, isole dependências e execute a aplicação.

Etapa A — Clonar com GitHub Desktop

  1. Abra o repositório da equipe e confirme que a base já foi publicada pelo instrutor.
  2. Se você não recebeu acesso de escrita: clique em Fork no GitHub, crie uma cópia na sua conta e depois clone a sua cópia. Isso permite publicar sem afetar o repositório original.
  3. No GitHub Desktop: File → Clone repository → URL; cole o endereço do repositório original (se tiver acesso) ou o endereço do seu fork.
  4. Escolha uma pasta local e clique em Clone. Abra o projeto no VS Code por Repository → Open in Visual Studio Code ou Open in your editor.
  5. Em Current Branch → New Branch, partindo de main, crie dev/seu-nome-sobrenome (use letras minúsculas e hífens).
  6. Confirme que a branch atual é a sua antes de começar as alterações. Publique com Publish branch quando estiver pronta.
Atenção: clonar um repositório público não concede permissão para enviar commits ao original. Utilize um fork, caso não tenha sido adicionado como colaborador. Não faça commits diretamente na main.

Etapa B — Criar ambiente virtual

Abra um terminal no diretório raiz do projeto. No Windows, use um dos ambientes abaixo.

Opção 1 · PowerShell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Opção 2 · Miniconda
conda create -n web-dev-day python=3.13 -y
conda activate web-dev-day

Problemas frequentes ao ativar o ambiente
Se o PowerShell bloquear o script de ativação, abra cmd e use .venv\Scripts\activate.bat; ou use o Python do ambiente diretamente. Se py não existir, tente python -m venv .venv. Uma mensagem de módulo ausente geralmente indica que a instalação ocorreu em outro ambiente.

Exemplo semelhante: como outro sistema separaria camadas?

Imagine uma API de livros, não de chamados. O controlador recebe GET /livros, pede uma listagem ao serviço, e o serviço consulta um repositório. Uma implementação de repositório poderia ler uma lista; outra poderia ler o PostgreSQL. O serviço conversa com a mesma interface nos dois casos.

Exemplo independente · biblioteca
from abc import ABC, abstractmethod

class RepositorioLivros(ABC):
    @abstractmethod
    def listar(self): ...

class ServicoLivros:
    def __init__(self, repositorio: RepositorioLivros):
        self.repositorio = repositorio

    def listar_disponiveis(self):
        return [livro for livro in self.repositorio.listar()
                if livro.disponivel]

A interface abstrata descreve operações; a classe concreta fornece os detalhes. O objeto é fornecido ao serviço pelo código que monta as dependências.

Backlog da sprint · quatro tickets

Trabalhe na ordem sugerida. Conclua um ticket antes de iniciar o próximo, execute testes e faça um commit específico para cada mudança. Não combine implementações diferentes no mesmo commit.

Convenção: o tipo aceito para refatoração é refactor. A abreviação refac não faz parte do padrão mais utilizado de Conventional Commits. Estrutura: tipo(escopo): descrição no imperativo.

WDD-001 · BUG REPORTfix

O filtro de chamados retorna registros incorretos

O suporte informa que, ao selecionar um status, a API apresenta chamados que não pertencem à seleção.

Prioridade: altaEsforço sugerido: 35 minÁreas: service · testes

Investigue

  1. Execute GET /chamados e anote os status existentes.
  2. Compare com GET /chamados?status_filtro=aberto.
  3. Procure o método responsável pela filtragem. Em qual camada ele deve ficar?
  4. Antes de alterar o código, descreva a condição correta em português.
  5. Corrija o defeito e crie um teste de regressão.

Critérios de aceite

  • Sem filtro, retorna todos os chamados.
  • Com filtro, retorna somente o status solicitado.
  • Um filtro sem correspondências retorna lista vazia.
  • O teste automatizado demonstra o comportamento correto.
  • As outras operações continuam funcionais.
Dica 1 · Por onde começar?
Comece comparando a entrada do controller com o argumento recebido pelo service. Depois localize a expressão que escolhe os itens da listagem. Uma condição booleana pode produzir o conjunto oposto do esperado.
Dica 2 · Exemplo parecido (catálogo de livros)

Imagine que uma biblioteca deseja consultar apenas livros da categoria solicitada. Primeiro reproduza o resultado com uma pequena lista e escreva uma asserção.

Exemplo independente · filtro por categoria
livros = [
    {"categoria": "ficcao", "titulo": "Livro A"},
    {"categoria": "historia", "titulo": "Livro B"},
]
esperados = [item for item in livros
             if item["categoria"] == "ficcao"]
assert len(esperados) == 1
Commit ao concluir: fix(chamados): corrigir filtro por status
WDD-002 · TECH DEBTrefactor

Uma regra de tratamento de dados está na camada errada

O time percebeu que o controller prepara textos antes de cadastrar chamados. Isso cria acoplamento entre HTTP e uma regra que também poderá ser usada por outras interfaces.

Prioridade: médiaEsforço sugerido: 30 minÁreas: controller · service

Seu trabalho

  1. Localize o tratamento de espaços em titulo, descricao e solicitante no cadastro.
  2. Decida por que essa transformação pertence ao serviço.
  3. Faça o controller apenas receber a requisição e delegar a criação.
  4. Mantenha o comportamento anterior dos dados cadastrados.
  5. Teste uma entrada com espaços nas extremidades.

Critérios de aceite

  • As três informações continuam sendo normalizadas.
  • A responsabilidade de normalizar dados está no serviço.
  • O controller fica mais simples e não modifica o objeto recebido.
  • Os testes iniciais continuam passando.
  • Nenhuma nova funcionalidade foi adicionada neste commit.
Dica 1 · Como distinguir refatoração de funcionalidade?
Refatorar é reorganizar o código sem mudar o que o usuário observa. Execute um teste antes da alteração, faça a mudança e execute o mesmo teste novamente. Compare as respostas HTTP.
Dica 2 · Exemplo parecido (cadastro de clientes)

Num cadastro de clientes, uma regra de formatação poderia inicialmente existir na rota. O ideal é que o serviço concentre essa regra, para que a API, uma CLI ou outra interface usem o mesmo comportamento.

Exemplo independente · serviço de clientes
class ServicoClientes:
    def __init__(self, repositorio):
        self.repositorio = repositorio

    def cadastrar(self, nome):
        nome_limpo = nome.strip()
        return self.repositorio.criar(nome_limpo)
Commit ao concluir: refactor(chamados): mover normalizacao para servico
WDD-003 · USER STORYfeat

Como atendente, quero concluir um chamado

Quando a solicitação for atendida, preciso registrar sua conclusão para que ela deixe de aparecer como pendente.

Prioridade: altaEsforço sugerido: 45 minÁreas: domínio · service · TAD · controller

Requisitos

  1. Crie PATCH /chamados/{chamado_id}/concluir.
  2. O endpoint não recebe corpo JSON.
  3. Um chamado existente e não concluído passa ao status concluido.
  4. Se não existir, responda 404.
  5. Se já estiver concluído, responda 409.
  6. O endpoint deve devolver o chamado atualizado.

Restrições arquiteturais

  • O domínio Chamado deve encapsular a ação de concluir em um método.
  • O serviço coordena o caso de uso e recebe um repositório por injeção.
  • Use o contrato abstrato existente; evite instanciar RepositorioMemoria no serviço.
  • A persistência passa pelo método salvar do repositório.
  • O controller traduz as situações em respostas HTTP.

Simule estes cenários no Swagger

Comportamentos esperados · não é implementação
PATCH /chamados/1/concluir  → 200, status "concluido"
PATCH /chamados/1/concluir  → 409, já concluído
PATCH /chamados/999/concluir → 404, não encontrado
Dica 1 · Quem é responsável por quê?
Entidade: altera seu próprio estado de forma válida. Service: busca, aciona a entidade e solicita gravação. Repository: armazena sem conhecer HTTP. Controller: interpreta erros e define códigos de resposta. Confira os métodos já disponíveis no contrato do repositório.
Dica 2 · Exemplo parecido (empréstimo de livros)

Um empréstimo deve poder ser devolvido somente uma vez. Observe como o próprio objeto pode proteger uma regra, sem precisar conhecer a rota HTTP.

Exemplo independente · domínio de biblioteca
class Emprestimo:
    def __init__(self):
        self.devolvido = False

    def devolver(self):
        if self.devolvido:
            raise ValueError("Livro já devolvido")
        self.devolvido = True

Como o serviço poderia buscar um empréstimo, chamar devolver() e armazenar o resultado? Que resposta HTTP caberia a uma segunda devolução?

Dica 3 · Injeção de dependências em FastAPI (outro domínio)
Exemplo independente · biblioteca
from fastapi import Depends

def obter_servico_livros():
    return ServicoLivros(RepositorioLivrosMemoria())

@router.get("/livros")
def listar_livros(servico = Depends(obter_servico_livros)):
    return servico.listar_disponiveis()

Na aplicação da sprint, use a função de dependências já existente, que compartilha a instância de repositório durante a execução.

Commit ao concluir: feat(chamados): permitir concluir chamados
